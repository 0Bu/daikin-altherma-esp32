# One finding KEY per line suppresses that ONE finding. Suppressed findings stay printed (as
# "suppressed by …") — an entry here is an adjudication ON RECORD, not a delete. Copy the `key:`
# line the audit prints for the finding you are adjudicating. A line that stops suppressing
# anything is itself a finding (D005): the condition it adjudicated is gone, so the line would only
# hide the condition coming back.
#

#
#   FORWARD-ARMED   A D002 (an entry matching no catalog label) whose copy is CORRECT and waiting
#                   for rows docs/REGISTERS.md documents but the offline profile generator does not
#                   emit yet. Deleting the copy instead would mean re-writing it when the rows land.
#                   Delete the line when they do — D005 will remind you.
#

# was built for (def/overlay.hpp shipped 11 such rows); the fix is copy in DESCRIPTIONS, not a line
# here. D003/D004 are malformed entries and have no legitimate adjudication either.
