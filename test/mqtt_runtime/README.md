# MQTT production runtime witness

The fixture compiles the complete current `main/mqtt_ha.cpp` and its production headers. MQTT/RTOS, clocks and unrelated services are deterministic host adapters; parsing uses the repository's lock-resolved espressif/cjson 1.7.19~2 component. No parser source is vendored here.

From the repository root, after managed dependency resolution:

```sh
python3 test/mqtt_runtime/run.py --real-cjson managed_components/espressif__cjson/cJSON
python3 test/mqtt_runtime/run.py --real-cjson managed_components/espressif__cjson/cJSON --ubsan
```

`--root` can select a checkout explicitly. `CC` and `CXX` select the host compilers. Each run creates its own directory through Python `tempfile`, respecting `TMPDIR`. It retains complete source snapshots, binaries, dependency files, exact commands and a manifest with source/cJSON/header/fixture hashes. It never writes repository files, downloads dependencies or deletes shared files.

Every entry of the `scenarios` list in `run.py` contains named assertions; a full run prints one `PASS <scenario> (<n> named checks)` line per entry. The scenarios cover:

- Real C++ allocation failure in reference/circulation status snapshots: normal delay, released activity/mutex ownership, preserved values/source-time watermarks and successful later iteration.
- Immediate source withdrawal after reconfiguration despite the next actual Config-copy allocation failure, followed by recovery.
- Consecutive failures increment every skip counter, log once per episode and rearm only after successful work.
- Both real cJSON production consumers: valid input, whitespace, quoted bracket/escape characters, depth16/17, malformed input, trailing data/NUL, wrong types, missing fields, and root/partial-tree allocation failures with balanced ownership.
- Long synthetic circulation probe topic: the post-subscribe cleanup owner/generation commit remains allocation-free, and later inactive cleanup unsubscribes that exact topic once.
- Saved circulation and three-topic room subscriptions: accepted SDK effects retain their exact cleanup owners without a subsequent allocation, including the final room-owner array commit.
- A saved circulation epoch changes inside the successful SDK call: stale status stays withdrawn, but the accepted topic remains owned and is unsubscribed once when disabled.
- Failed first subscriptions, partial room batches and failed re-subscriptions: retain accepted or still-live prior owners, report incomplete subscription status, retry without resetting the source and eventually unsubscribe each accepted topic once.
- Clean-session reconnect with unchanged long accepted owners: real C++ allocation failures in both room mapping copies, all three desired-topic copies and the circulation owner copy cannot consume the pending resubscription. The failed call releases locks without an SDK subscribe; the next production service call restores actual broker subscriptions, truthful status and current wire-value acceptance.
- Rejected unsubscribe on deletion, replacement and both probe teardown paths: preserve exact live cleanup ownership, defer replacement effects until retirement succeeds and accept one eventual unsubscribe per topic.
- One topic shared by room, saved circulation and probe owners: retiring each owner preserves the remaining subscription until the final owner releases it.
- A new active probe starts before the prior inactive cleanup cycle: retire the previous owner before the new SDK effect, preserve it on rejection, and judge shared ownership from accepted subscriptions rather than saved configuration.
- SDK-owned callbacks record the transport task's stack; caller-side error/disconnect callbacks cannot misfile that sample under the SDK or publisher slot.
- Heartbeat, Weather and heating-curve emitters: inspect actual topic, payload length, QoS/retention and independently expected typed wire fields with real cJSON. Flat bounded SDK traces allocate no C++ storage. Weather tests suppress unconfigured/unchanged output, retain the last accepted cache on SDK rejection, retry later and commit without allocation after acceptance.
- Consent opt-out/opt-in inside one cycle and a room-source switch forget the prior heating-curve event and cadence at the reconfiguration call, allocation-free and lock-balanced; the new scope's first eligible reading records at once with sequence and counters continuing. Without the mutex the call touches no sampler state. A reconfiguration injected between the evaluator's room read and its evaluation lock records nothing from the stale reads, allocation-free under the mutex.
- Scalar HP/Crash helpers preserve first-source permission, current publication permission, confirmed source withdrawal and changed/dismissed crash evidence.
- All five discovery builders round-trip accepted quote/backslash/UTF-8 topics through real cJSON; transport/source availability entries are checked, and default identities and unaffected fields remain stable.
- Actual DATA fragments reach the queue and source owner only when complete and consecutive. Boundary sizes, source cutover, overflow, timestamp rollback and retained input without source time have independent assertions.
- Probe captures belong to their original test generation; save proof expires with the original source observation even after clock rollback or queue delay.
- Initial transport-start rejection retains the initialized client, backs off and restores inbound service without reboot; rejected event registration reports its cause before any unobserved transport can start.
- Actual frozen retired heartbeat/crash and value-identity retirement under the current installation namespace: rejected enqueue, no PUBACK, wrong message id/epoch, same-client reconnect, outbox expiration and stopped/replaced transport retain the exact cursor. Source and discovery cleanup never admit QoS-1 tombstones concurrently. Replacement discovery waits for the required acknowledgements; ongoing source/heartbeat telemetry remains independent.
- Retained-topic probes retry rejected subscriptions, preserve retained evidence past the probe deadline when deletion fails, wait for matching PUBACK, and retain cleanup ownership on rejected unsubscribe. A clean broker receives no empty publish.
- Real C++ allocation failures before topic preparation and after admitted SDK effects preserve cleanup cursors and in-flight ownership. PUBACK before enqueue return remains captured; evidence overflow requires a stopped transport before retry.
- A real profile-to-profile cutover retires its obsolete current grouped configs and fault companions before replacement discovery. Common/new topics and other installation namespaces are preserved.
- Periodic HomeHub/forecast discovery retirement executes the actual task timer and shared PUBACK cursor: rejected enqueue, missing/wrong ACK, outbox expiry, reconnect and stopped transport preserve every frozen ledger item. Source withdrawal takes the next vacant slot; current telemetry continues while a ledger ACK is delayed.
- A real `altherma_gshp2` → `generic` → `altherma_gshp2` return delays the entering-brine config's delete ACK and then requires the full original discovery set again. The last possibly announced journal profile remains P throughout the interrupted Q transition.
- A valid late common-row cursor across two real 137-row profiles remains Pending after its bounded comparison slice. Preparation/comparison consumes no C++ allocation; the next slice preserves the late common config. Pure checks cover exact component/group/slug and companion collisions plus the fixed identity capacity across every shipped profile.
- A started retirement continues from the actual pre-publication cleanup step after the active profile returns to `auto`. Requested source withdrawals take the next vacant cleanup slot rather than waiting behind a large legacy pass; its frozen cursor later finishes without announcing a replacement profile.
- Durable scoped predecessor load and target save ordering: actual MQTT callers use a bounded Store-API adapter. A reset midway through the ACK cursor re-loads the predecessor and repeats idempotent deletes; a reset after save but before discovery re-loads the target without rewriting it. A failed commit may write the target through only after every predecessor delete was confirmed; same-boot save never claims reboot restoration.
- A prior profile's historical grouped config is retired even when that row is detect-only or quarantined in the current definitions; its current publication filter cannot hide an older retained predecessor.
- Store read/commit rejection, corruption, unknown profiles and real allocation failure retain provenance and retry with bounded intervals. Raw-base and full-board mismatches are separately tested operator boundaries; no foreign namespace is deleted. Missing/empty records do not invent a pre-upgrade model, and `auto` or an empty target never overwrites the prior profile. Journal failure defers discovery while the actual task continues current X10A seeds, changes and source availability.
- The complete production task loop receives controlled X10A, HomeHub, ENV III, Weather and crash snapshots. Never-seen X10A, an empty sweep at 14 seconds, withdrawal at exactly 15 seconds and recovery preserve independent telemetry and subscriptions on one initial LWT client. A fresh accepted X10A seed precedes source online; unchanged revision cannot bypass a recovery reseed.
- HomeHub expiry with no new revision and ENV III expiry with no new sample remove retained readings. A reconnect seeds current source liveness rather than old values. Disable and enabled peer replacement suppress predecessor publication until their exact PUBACK cleanup completes.
- SDK rejection of initial/outage source-offline, transport-online, source-online and changed X10A state preserves the last accepted marker/generation and retries. Config-copy OOM cannot prevent allocation-free withdrawal or draining an already delivered cleanup ACK.
- Distinct full-MAC boards with the same last three bytes receive distinct client and secondary device IDs. A failed eFuse read prevents client initialization/start and reports an explicit error. Automatic cleanup never guesses ownership of a short-MAC-era namespace.

Every entry of the `mutations` inventory in `run.py` is a temporary whole-production-source mutant that must fail its expected named assertion; a full run prints one `REJECTED <name>` line per entry. They independently break allocation/lock ownership, subscription epochs and retries, wire fields and suppression, source freshness and availability, hardware identity, cleanup admission/ACK/cursor/fairness, or journal load/save ordering and error handling. New controls restore the periodic admission/timer defects, the P→Q→P announcement/cache defects, and allocating, unbounded or falsely complete replacement scans. Compile failure, crash or a different assertion is not accepted as mutation evidence.

`--scenario NAME` may be repeated to run selected scenarios and their associated compiling negative controls; an omitted selector runs the full inventory. The manifest records the actual selection.

This is bounded host evidence. Real broker/TLS/reconnect timing, ESP32-S3 scheduling/stack margin, device heap geometry, physical reboot/power-loss restoration and plant truth require separate evidence. The complete production task loop, all source emitters, X10A discovery cutover and all five discovery builders execute with controlled service snapshots. The poll/Modbus/ENV adapters test MQTT ownership and output, not physical acquisition. MQTT caller resets preserve only the Store adapter's durable record and broker-confirmed tombstones; `test/mqtt_retirement_store/` separately executes the real NVS adapter and codec. Frozen cleanup is restricted to the current owned namespace and known profile definitions; it cannot classify pre-upgrade short-MAC or colliding slug namespaces or an unknown former model. Existing X10A discovery that references only the old transport topic requires explicit operator migration before accepting a first-upgrade never-seen-X10A case. Missing and foreign records report those owner boundaries rather than inventing deletion authority.
