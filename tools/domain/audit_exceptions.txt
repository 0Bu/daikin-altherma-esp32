# Domain-audit adjudication ledger — tools/domain/catalog_audit.cpp
#
# One finding key per line suppresses that ONE finding (never a whole check). Suppressed findings
# stay printed under "suppressed by …" — an entry here is an adjudication ON RECORD, not a delete.
# Copy the `key:` line the audit prints for the finding you are adjudicating.
#
# Two kinds of entry, and the difference matters:
#
#   ADJUDICATED   The deviation is CORRECT for this model. docs/REGISTERS.md:196-200 is explicit
#                 that the §5 table is a representative model and that families differ — so a real
#                 difference is expected and permanent. Needs evidence: a live capture, or a
#                 documented model fact. Never "it looked fine to me".
#
#   KNOWN-DEFECT  The finding is REAL and not yet fixed. Temporary. Carries the tracking issue and
#                 must be deleted in the PR that fixes it — a KNOWN-DEFECT entry that outlives its
#                 fix silences the guard that would catch the fix regressing.
#
# NEVER add an entry to make a NEW finding go away. A finding on code the PR touches is the gate
# doing its job; adjudicating it away is how -971.5 °C shipped in the first place. If a finding is
# wrong because the AUDIT is wrong, fix the audit — that is a bug in the check, not a fact about
# the catalog. (Converter ids that decode identically at a given width — conv 101 vs 152 on a
# 1-byte field — are already proven equivalent by execution and never reach this file.)
#
